# Crashpad 0.3.0

The first release prepared for the GitHub App path: a GitHub App service, plus a companion on your own computer that runs checks and Claude repairs.

**Status: the GitHub App path has not run against github.com yet.** It is tested against a fake GitHub only. The live [acceptance test](../acceptance.md) has not been performed. The local CLI (`check`, `repair`, `setup`) has been used on two real projects; see [validation](../validation.md).

## Install

Crashpad is not on npm. Download `crashpad-0.3.0.tgz` from this release, then:

```sh
npm install -g ./crashpad-0.3.0.tgz      # Node.js 22.18 or later
crashpad --version                       # 0.3.0
crashpad setup                           # prerequisites, Claude Code, and repository discovery
```

Requirements:

- Git;
- PostgreSQL 13+ for database checks: Crashpad creates and drops only `crashpad_*` databases;
- Claude Code, optional, only for repairs.

To build the same archive from source: `git clone https://github.com/recalculator/crashpad && cd crashpad && npm ci && npm pack`.

## New in 0.3.0

- **Runtime scenarios outside the repository:** `crashpad scenarios --import <file>` keeps `crashpad.http.json`-format scenarios in Crashpad's storage. A project needs no Crashpad file to get API, permission, and workflow checks. A repair cannot change the stored expectations.
- **Drizzle schema compatibility** for projects without committed migrations, for example `drizzle-kit push` projects. It is labelled as schema compatibility, never as migration testing.
- **Project commands:** the project's own build, typecheck, and test scripts run on both versions and are reported separately from Crashpad's checks.
- **Builds** get the test environment and a throwaway database; a committed example database URL is never used.
- **Service deployment package** (`deploy/`, inside the archive):
  - an installer, a systemd unit, a daily backup timer, and `backup.sh`;
  - a Caddyfile that exposes only the service's paths;
  - `healthcheck.sh`.
- **Service tooling:**
  - `crashpad service check [--online]` validates the configuration, and the service refuses to start without a valid one;
  - `crashpad service register --url https://<host>` registers the App from its manifest and saves the credentials locally with mode 600;
  - `/healthz` reports the version and whether the state can be written.

## Verified, and how

| What | How |
|---|---|
| Install from the archive outside the source checkout | Automated test, plus a manual rehearsal of the installed service: configuration check, `/healthz`, signed webhook, restart, persistence, backup |
| Five check areas, repair, stored scenarios, schema compatibility | 229 automated tests against real PostgreSQL 16, Git, and application processes |
| Live Claude Code repair | Verified on two real projects (Willo, autofounder) with the packaged CLI |
| GitHub App service and companion | **Fake GitHub only** |
| Manifest registration, `service check --online` | **Fake GitHub only** |
| systemd units, `install.sh`, Caddyfile | **Not run on a real host** |

## Known limitations

- Automatic discovery supports Node.js/TypeScript with PostgreSQL only.
- Permission and workflow expectations are never inferred: they come from scenarios you write.
- The service is a single process with file-based state; run one replica.
- Not tested: Windows, and PostgreSQL other than 16.
